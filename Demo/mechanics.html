What keeps the tags different? Exact integers preserve every bit, and a counter avoids repeats inside one generator. Your system must assign distinct computer numbers to concurrent generators and manage restarts safely. IDs are identifiers, not passwords or secrets.
Expert detail: exact bits and failure behavior
Time component calculation
—
id = (elapsed << 22) | (machineId << 12) | sequence

After 4,096 IDs in one millisecond, generation throws ERR_SEQUENCE_EXHAUSTED without spinning. A backward clock throws ERR_CLOCK_ROLLBACK until it catches up. Both failures preserve generator state.

The arrows show deployment and event flow. There is no live synchronization connection between the generators. The application or infrastructure manages configuration, machine allocation, and clock synchronization.

Label an event

Attach an ID and a timestamp to telemetry or application events. Treat the ID as a convenient label, not a guarantee of uniqueness.

Follow a journey

Generate once at the start of an operation and pass that same ID through downstream calls. Use your tracing system’s trace ID when following a standard such as W3C Trace Context.

Work from many desks

Different machines can generate locally. Uniqueness requires distinct machine allocation, the same epoch, safe restarts, and handling the documented clock and capacity errors. Enforce database uniqueness as a final guard.

  1. Pin and deploy the same package version. Pin a released version, then commit package.json and package-lock.json. The v4 candidate on this branch has not been published yet. Use npm ci in deployments. Update the pinned version deliberately, test it, and roll it out across services. npm distributes code; it does not synchronize clocks, configuration, or generated IDs.
  2. Choose one shared epoch. Store it in shared deployment configuration and keep it stable. Consumers need that same epoch to decode IDs. An ID does not include its epoch or npm version.
  3. Assign each concurrent generator its own machine ID. Use an explicit deployment allocation from 0 to 1023. Two replicas of one service also need distinct IDs; do not randomly select IDs or give every replica the same environment value.
  4. Synchronize host clocks. Use your infrastructure’s time synchronization service (such as NTP). Monitor clock skew and rollback. The generator detects backward clock changes and throws; your application decides when and how to retry.
  5. Initialize once per process. Create one generator instance per allocated machine ID. Keep it at process scope; do not create a new instance per request. Preserve a restart watermark or wait beyond the last timestamp issued before reusing that machine ID. For logs or events, pass the generated ID to other services instead of regenerating it there.

npm pack
# Install the locally built candidate tarball in your application
npm install --save-exact /path/to/Particle-4.0.0-rc.1.tgz

npm ci
// Run once at service startup (Node 24 or Node 26).
const { createGenerator, decode } = require('Particle')

const rawMachineId = process.env.PARTICLE_MACHINE_ID
const rawEpoch = process.env.PARTICLE_EPOCH_MS
if (!rawMachineId?.trim() || !rawEpoch?.trim()) {
  throw new Error('Set an allocated machine ID and shared epoch')
}
const generator = createGenerator({
  machineId: Number(rawMachineId),
  epoch: Number(rawEpoch)
})

// In a request or event handler:
const id = generator.nextString()
const event = { id, idEpoch: generator.epoch }
const fields = decode(event.id, { epoch: event.idEpoch })
console.log(JSON.stringify({ ...event, timestamp: fields.timestamp }))
Uniqueness has a scope. Generators with the same machine ID and epoch can collide if their lifetimes overlap or restart at an already-issued timestamp. v4 does not allocate machine IDs, persist state, synchronize clocks, or provide global ordering between machines. Number-based v3 IDs use a different format and must not be decoded as v4 IDs.

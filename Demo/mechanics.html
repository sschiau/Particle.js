Label an event

Attach an ID and a timestamp to telemetry or application events. Treat the ID as a convenient label, not a guarantee of uniqueness.

Follow a journey

Generate once at the start of an operation and pass that same ID through downstream calls. Keep a standard trace ID when reliable correlation is required.

Work from many desks

Different machines can generate locally. For database primary keys or guaranteed uniqueness, use another generator or enforce uniqueness and handle collisions.

  1. Pin and deploy the same package version. Commit package.json and package-lock.json. Use npm ci in deployments. Update the pinned version deliberately, test it, and roll it out across services. npm distributes code; it does not synchronize clocks, configuration, or generated IDs.
  2. Choose one shared epoch. Store it in shared deployment configuration and keep it stable. Consumers need that same epoch to decode IDs. An ID does not include its epoch or npm version.
  3. Assign each concurrent generator its own machine ID. Use an explicit deployment allocation from 0 to 1023. Two replicas of one service also need distinct IDs; do not randomly select IDs or give every replica the same environment value.
  4. Synchronize host clocks. Use your infrastructure’s time synchronization service (such as NTP). Monitor clock skew and rollback. This library does not detect or correct backward clock changes.
  5. Initialize once per process. Particle is a shared global singleton. Set its configuration at startup, not per request. For logs or events, pass the generated ID to other services instead of regenerating it there.
# Install a pinned version, then commit both package files
npm install --save-exact Particle@3.0.2
# On deployment, install exactly what the lockfile specifies
npm ci
// Run once at service startup (supported Node 24 or Node 26).
require('Particle')
const generator = globalThis.Particle

const machineId = Number(process.env.PARTICLE_MACHINE_ID)
const epoch = Number(process.env.PARTICLE_EPOCH_MS)
if (!process.env.PARTICLE_MACHINE_ID?.trim() || !Number.isInteger(machineId) || machineId < 0 || machineId > 1023) {
  throw new Error('Assign this process a unique machine ID from 0 to 1023')
}
if (!Number.isSafeInteger(epoch) || epoch < 1000000000000 || epoch > Date.now()) {
  throw new Error('Set a stable, shared epoch in milliseconds')
}
generator.machineId = machineId
generator.epoch = epoch

// In a request or event handler:
const id = generator.generateParticle()
const timestamp = generator.timeFromParticle(id)
console.log({ id, timestamp })
Synchronization does not fix this implementation’s limits. JavaScript Number loses integer precision at this size, and the sequence is random rather than a coordinated counter. Even with distinct machine IDs and synchronized clocks, collisions remain possible. Do not use these IDs as secrets or promise globally unique, strictly ordered identifiers.
